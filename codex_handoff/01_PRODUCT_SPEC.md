# Product Spec

## 1. 문제

할인은 많지만 사용자는 자신이 가진 조건 중 무엇을 사용하면 **지금 가장
싸게 결제할 수 있는지** 알기 어렵다.

정보는 카드사, 통신사, 멤버십, 판매처, 이벤트 페이지 등에 흩어져 있다.
사용자는 어떤 할인이 존재하는지 자체를 모르는 경우도 많다.

## 2. 제품 정의

사용자 프로필과 현재 웹 정보를 결합해 특정 구매/방문 대상에 대해 적용
가능한 할인을 찾고, 예상 최저 결제 금액을 계산하는 개인화 할인 검색기.

예: - Profile: 26세 / 서울 / 대학생 / SKT / 현대카드 ZERO Edition3 /
네이버플러스 - Query: `에버랜드` - Output: 적용 가능한 할인, 조건, 근거
출처, 정가, 예상 결제가, 절약액, 대안

## 3. 핵심 가치

사용자가 원하는 것은 "할인 정보 목록"보다 다음 질문의 답이다.

> 그래서 나는 얼마에 살 수 있는데?

## 4. MVP 범위

### 포함

-   사용자 혜택 프로필
-   자연어 검색
-   구매/방문 의도 구조화
-   프로필 기반 할인 탐색
-   판매처 자체/현재 프로모션 탐색
-   공식 출처 우선
-   할인 조건 구조화
-   eligibility 3상태
-   base price 확인
-   예상 결제가 계산
-   최저가 정렬
-   출처 표시
-   PC + 모바일 반응형

### 제외/후순위

-   카드번호/주민번호/결제내역 수집
-   결제 기능
-   모든 한국 할인정보 자체 DB 구축
-   복잡한 로그인
-   완벽한 할인 중복 조합 최적화
-   모든 쇼핑 카테고리 완벽 지원
-   자동 결제/쿠폰 발급

## 5. Eligibility 상태

-   `confirmed`: 현재 프로필과 확인된 조건으로 적용 가능
-   `needs_info`: 혜택은 존재하지만 프로필 정보가 부족함
-   `not_eligible`: 확인된 조건상 적용 불가

## 6. 두 종류의 탐색

### Personal Search

사용자가 이미 가진 조건 × 대상 - 카드 - 통신사 - 멤버십 - 나이 -
직업/신분 - 지역

### Discovery Search

프로필에 없어도 현재 대상에 존재하는 공개 할인 발견 - 판매처 프로모션 -
간편결제 이벤트 - 쿠폰 - 제휴 - 기간 한정 이벤트

두 결과를 섞지 않는다. - `지금 바로 받을 수 있는 가격` -
`조건을 추가하면 가능한 가격`
